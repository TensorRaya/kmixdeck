# `kmixdeck` — command-line reference

🔴 **This page has moved.** The CLI reference has lived since CL-1 in
[`kmixdeck.md`](kmixdeck.md) and is structured according to **man-pages(7)**. From
this single source three outputs are generated:

| Output | How | For what |
|---|---|---|
| `man kmixdeck` | `docs/generiere-doku.py man` → `kmixdeck.1` (CMake, not checked in) | The full reference on the system |
| `kmixdeck --help` | `docs/generiere-doku.py help` | One page, only NAME/SYNOPSIS/EXAMPLES/OPTIONS |
| this file | Pointer to the source | So that no second text arises that drifts |

**Why no second full text here:** documentation that lives in two places is after
the third commit wrong in one of them — and nobody knows which. Maintaining a
duplicate costs more than it is worth, so there is none.

## Changing

```sh
$EDITOR docs/kmixdeck.md          # der einzige Ort, an dem Text stehen darf
python3 docs/generiere-doku.py pruefen   # Abschnitte + Reihenfolge nach man-pages(7)
python3 docs/generiere-doku.py man | groff -man -Tutf8 -ww -z   # muss warnungsfrei sein
man -l <(python3 docs/generiere-doku.py man)                    # so sieht es aus
```

`pruefen` rejects invented section names: only NAME, SYNOPSIS,
DESCRIPTION, EXAMPLES, OPTIONS, COMMANDS, REFERENCES, EXIT STATUS, FILES,
SEE ALSO, NOTES — in this order. Topics without their own man section
(Levels, Slugs, port references) are subsections
(`##` → `.SS`) under REFERENCES; scripting notes live in NOTES.

`kmixdeck.1` is **not checked in**, but generated by CMake on every build from
`docs/kmixdeck.md` (target `manpage`). A checked-in generated file is an
invitation to edit it by hand.
